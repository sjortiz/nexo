Graph RAG that shows its work.

Nexo turns documents into a knowledge graph, lets an agent trace how people, organizations and facts connect across them, and answers with a citation for every claim. A person approves each answer before it is released.

How it works

Four stages, from raw documents to an answer someone has checked. Every node and edge in the graph points back to the passage it came from, so nothing is trusted without its source.

Ingest

Documents are split along their headings, classified for sensitivity, and read by an LLM that extracts entity-relation-entity facts, each with a verbatim quote that must appear in the passage.

Connect

Entity resolution merges "Acme Holdings Inc.", "Acme" and "AHI" into one node. A relation vocabulary maps "bought" and "acquired by" onto one canonical edge. Everything lands in Neo4j.

Investigate

A Strands agent writes read-only Cypher to trace multi-hop paths, then reads the exact passages behind each edge. It decides what to follow; LangGraph fixes the workflow around it.

Review

Compliance checks flag uncited claims, citations to text the agent never read, and sensitive data. The run pauses until a reviewer approves or rejects, even days later.

What makes it different

Built for answers you can audit, on infrastructure you control.

Grounded by construction

Extracted facts need a quote found in the passage; answers need a citation per claim; citations must point at text the agent actually read.

One node per entity

Normalization, aliases and a cautious model arbiter merge names across documents. Every merge is recorded and undone when its document is withdrawn.

Hybrid retrieval

BM25 keyword search catches exact names and codes; vectors catch paraphrases. Reciprocal Rank Fusion combines both, accent-insensitive.

Human in the loop

LangGraph checkpoints the run at the review step. Approve or reject from the CLI, from another process, or after a restart.

Sensitivity-aware

Chunks are classified public, internal, PII or PHI. Callers only see what a source within their clearance supports; PHI reliance blocks release until acknowledged.

Use it from Claude

An MCP server exposes read-only tools, and a Claude Code skill walks the model through orient, locate, trace, read and answer, with citations.

Observable

OpenTelemetry GenAI conventions end to end: workflow, nodes, agent, tools, model and database spans. Message content stays out of traces by default.

Runs where you are

vLLM on GPU servers, or Ollama on a Mac or Linux box chosen by a hardware profile such as m1-max-64 or gpu-24. Split roles across two machines.

Built on

Quickstart

Local models on one machine with Ollama. How the pieces connect: how local setup works. For two machines or Linux, see the Apple Silicon and Linux playbooks.

Set up

git clone https://github.com/sjortiz/nexo.git && cd nexo
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
cp deploy/local/local.env.example .env   # set LOCAL_PROFILE, NEO4J_PASSWORD
deploy/local/ollama-setup.sh m1-max-64   # pulls and preloads the models
podman compose up -d neo4j otel-collector jaeger
nexo models --check                      # every role's model, reachable?

Ask

nexo ingest corpus/memo.md --doc-type memo
nexo ask "How is Acme Holdings connected to Gamma Clinics?"
nexo review <thread_id> --approve --reviewer you@example.com

# or from Claude Code: the repo ships .mcp.json and a skill
nexo mcp

Where it stands

An honest account, kept short.

Verified

  • CI on Ubuntu and macOS, including Neo4j integration tests on a real database.
  • The agent loop, workflow and MCP protocol run for real in tests; only the model server is scripted.
  • Safeguards are mutation-tested: removing one makes a test fail.
  • Docs stay in sync with the code: diagram, settings and tool lists are checked.

Not yet

  • Live model runs are opt-in (NEXO_LIVE=1), not in CI.
  • GPU passthrough for the vLLM containers is untested here.
  • Open design questions: updates, contradictions and error propagation, in the design review.
