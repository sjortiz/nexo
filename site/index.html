Graph RAG · Agents · Human review

Graph RAG that shows its work.

Nexo turns documents into a knowledge graph, lets an agent trace how people, organizations and facts connect across them, and answers with a citation for every claim. A person approves each answer before it is released.

How it works

Four stages, from raw documents to an answer someone has checked. Every node and edge in the graph points back to the passage it came from, so nothing is trusted without its source.

Ingest

Documents are split along their headings, classified for sensitivity, and read by an LLM that extracts entity-relation-entity facts, each with a verbatim quote that must appear in the passage.

Connect

Entity resolution merges "Acme Holdings Inc.", "Acme" and "AHI" into one node. A relation vocabulary maps "bought" and "acquired by" onto one canonical edge. Everything lands in Neo4j.

Investigate

A Strands agent writes read-only Cypher to trace multi-hop paths, then reads the exact passages behind each edge. It decides what to follow; LangGraph fixes the workflow around it.

Review

Compliance checks flag uncited claims, citations to text the agent never read, and sensitive data. The run pauses until a reviewer approves or rejects, even days later.

What makes it different

Built for answers you can audit, on infrastructure you control.

Grounded by construction

Extracted facts need a quote found in the passage; answers need a citation per claim; citations must point at text the agent actually read.

One node per entity

Normalization, aliases and a cautious model arbiter merge names across documents. Every merge is recorded and undone when its document is withdrawn.

Hybrid retrieval

BM25 keyword search catches exact names and codes; vectors catch paraphrases. Reciprocal Rank Fusion combines both, accent-insensitive.

Human in the loop

LangGraph checkpoints the run at the review step. Approve or reject from the CLI, from another process, or after a restart.

Sensitivity-aware

Chunks are classified public, internal, PII or PHI. Callers only see what a source within their clearance supports; PHI reliance blocks release until acknowledged.

Use it from Claude

An MCP server exposes read-only tools, and a Claude Code skill walks the model through orient, locate, trace, read and answer, with citations.

Observable

OpenTelemetry GenAI conventions end to end: workflow, nodes, agent, tools, model and database spans. Message content stays out of traces by default.

Runs where you are

vLLM on GPU servers, or Ollama on a Mac or Linux box chosen by a hardware profile such as m1-max-64 or gpu-24. Split roles across two machines.

Built on

Open components throughout, each documented with the features Nexo uses.

Run it

From a clean machine to a reviewed answer, on one Mac or Linux box with local models. The model download is 8 to 33 GB depending on your machine. Other layouts are below the steps. The repository's Makefile runs each step: make install env up check; make lists every target.

  1. Install the prerequisites

    uv for Python and the dependencies (it installs Python 3.12 itself), Ollama for the models, and Podman for Neo4j and tracing.

    # macOS
brew install uv ollama podman
podman machine init && podman machine start
# Linux: curl -LsSf https://astral.sh/uv/install.sh | sh, curl -fsSL https://ollama.com/install.sh | sh,
# then podman from your package manager

  2. Get Nexo

    git clone https://github.com/sjortiz/nexo.git && cd nexo
uv sync && source .venv/bin/activate     # Python 3.12 and the locked dependencies

  3. Describe your setup

    One file, nexo.yaml, says how models are served and what runs beside Nexo. Start from a preset (mac-single, mac-two-machines, linux-cpu, linux-gpu, linux-vllm) and set your profile: the chip and memory on a Mac (m1-max-64, m5-pro-24), or gpu-<VRAM GB> / cpu-<RAM GB> on Linux. make env also generates the passwords into your OS keychain (~/.config/nexo/config where there is none), never into a file you copy.

    make env PRESET=mac-single
python3 src/nexo/local_profiles.py plan m5-pro-24   # the models a profile picks
# in nexo.yaml: models.local.profile: m5-pro-24

  4. Start everything

    Pulls and starts the profile's models in Ollama, then Neo4j, the collector and SigNoz, which shows traces, metrics and logs at http://localhost:8080 (log in with SIGNOZ_USER_EMAIL and uv run keyring get nexo/nexo SIGNOZ_USER_PASSWORD). Langfuse, Jaeger and LangSmith are add-ons: turn one on in nexo.yaml, or for one run with make up LANGFUSE=1.

    make up

  5. Check

    The preflight (container engine, secrets, memory) and every model role should say ok. Otherwise the output names the server that did not answer or the model it is missing.

    make check

  6. Ingest and ask

    Put Markdown or text files in corpus/. ask prints thread <id>: awaiting_review with the answer, its citations and any findings; a reviewer then approves or rejects it.

    nexo ingest corpus/memo.md --doc-type memo
nexo ask "How is Acme Holdings connected to Gamma Clinics?"
nexo review <thread_id> --approve --reviewer you@example.com

  7. Or ask from Claude Code

    The repository ships .mcp.json, which starts nexo mcp, and a skill that makes Claude cite every claim. Approve the nexo server when asked.

    claude   # started in the nexo directory
Two machines: a big one for the agent

The big machine serves the agent and extraction models; this one serves the rest and runs Nexo. Clone the repository on both. On a Mac, enable Remote Login on the big one.

# on the big machine
deploy/local/ollama-setup.sh m1-max-64 heavy
# here
make env PRESET=mac-two-machines
ssh -N -L 11435:127.0.0.1:11434 you@m1-max.local   # keep it running
make up
nexo models --check
Linux notes

The Ollama installer runs it as a systemd service, so apply the settings make up prints. The Nexo container shares the host network to reach Ollama; nexo setup sets that up.

make env PRESET=linux-gpu      # or linux-cpu, or linux-vllm for vLLM on NVIDIA GPUs
sudo systemctl edit ollama      # add the printed OLLAMA_* lines under [Service]
sudo systemctl restart ollama
make up
Without containers

Install Neo4j natively and skip make up; set LOCAL_PROFILE, NEO4J_URI and NEO4J_PASSWORD in .env and start the models with make models. Tracing is optional: leave OTEL_EXPORTER_OTLP_ENDPOINT unset.

brew install neo4j
neo4j-admin dbms set-initial-password <password>
brew services start neo4j
Nexo in a container

Files in ./corpus are mounted at /corpus; the container reaches Ollama on the host.

make app ARGS="ingest /corpus/memo.md --doc-type memo"

How the pieces fit together

Models run in Ollama, picked by a hardware profile. Three choices, each made on its own, and one command to check the result.

Which models

Name the machine with a profile: m1-max-64, m5-pro-24, gpu-24, cpu-64. Memory picks the largest model tier that fits. Set LOCAL_PROFILE.

One machine or two

Add REMOTE_PROFILE and a second machine serves the heavy models (agent, extraction) through an SSH tunnel. The rest stays local.

Podman or native

Neo4j and Nexo run as containers or as plain installs; tracing runs in containers or stays off. The models stay native either way, so they can use the GPU.

One catalog, two readers

A single profile catalog decides the models. The setup script reads it on each model machine to pull the models and size Ollama (context length, parallelism, memory). Nexo reads it to pick the model and server for each role. Anything you set explicitly, like AGENT_MODEL, wins.

Keep the role sets matched

One machine uses the single set. With two, run the script with heavy on the remote machine; locally it picks light by itself when .env has REMOTE_PROFILE. Then nexo models --check confirms every role's server answers and has its model, and exits non-zero if not.

Where it stands

An honest account, kept short.

Verified

  • CI on Ubuntu and macOS, including Neo4j integration tests on a real database.
  • The agent loop, workflow and MCP protocol run for real in tests; only the model server is scripted.
  • Safeguards are mutation-tested: removing one makes a test fail.
  • Docs stay in sync with the code: diagram, settings and tool lists are checked.

Not yet

  • Live model runs are opt-in (NEXO_LIVE=1), not in CI.
  • GPU passthrough for the vLLM containers is untested here.
  • Open design questions: updates, contradictions and error propagation, in the design review.
