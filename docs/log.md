# Bundle Update Log

## 2026-10-20
* **Update**: Thread results carry an `outcome` (`rejected: no releasable output`, `rejected by <reviewer>`, `approved by <reviewer>`) and the CLI prints it after `completed`, so a system rejection no longer reads as success; `status` values are unchanged ([Request lifecycle](architecture/request-lifecycle.md#result), ADR-0003 amended).
* **Update**: `nexo mcp`'s `nexo_search` and `nexo_get_chunks` mask detected PII like the agent instead of withholding the chunk; search returns a masked chunk only when the query matches its masked text, so fragments of a masked value (`0134`, `jane`) do not find it; graph tools drop chunk text from their rows, rank `:Chunk` maps by level, count `MENTIONED_IN` surfaces as PHI, and the Cypher guard rejects reading chunk text by name ([MCP server](components/mcp-server.md#safeguards), [read-time redaction](components/sensitive-data-detection.md#read-time-redaction), ADR-0006 amended).
* **Update**: Citations written without `chk_` (`[chunk:714c2e550aacdb8f]`) count when the hash is the whole 16 hex characters and `chk_` plus it is a chunk the agent read in that run; shortened or unknown hashes stay uncited, and the prompts ask for the whole id, including its `chk_` prefix ([Investigator agent](components/investigator-agent.md#output)).
* **Update**: `make up` copies a checkout's old `.data/checkpoints.sqlite` to `<data dir>/<stack>/` when the stack has none, so reviews paused before the move survive the upgrade; an existing file is never overwritten ([ADR-0018](decisions/adr-0018-chunks-in-neo4j.md)).
* **Update**: CLI logs go to stderr; stdout carries only the command's JSON (`nexo ask ... | jq`), and `nexo eval` / `eval-extraction` write one JSON object per line ([Observability](operations/observability.md#logs)).
* **Update**: `spec.ports` in `nexo.yaml` sets the host ports the stack publishes; `nexo.env`, the lock, the Neo4j login probe and the printed links follow, and `check` names whoever holds a port already, so a second stack can run beside the first.
* **Update**: The investigator has [find_paths and entity_neighbours](components/graph-lookup-tools.md): fixed path and neighbour lookups by entity key, so small models no longer write that Cypher; paths and edges above the caller's clearance are withheld, and unranked edges count as PHI ([Investigator agent](components/investigator-agent.md)).
* **Creation**: [Review in Agent Inbox](operations/agent-inbox.md): an opt-in `agentInbox` add-on (`AGENT_INBOX=1`, `make review-inbox`) renders LangChain's archived, MIT-licensed Agent Inbox from a pinned commit and an adapter that sends every decision to `Runtime.review` ([ADR-0019](decisions/adr-0019-review-surfaces.md)).
* **Creation**: A [demo review page](operations/human-review.md#demo-review-page) (`make review-ui`): no authentication, loopback only, off unless started.
* **Update**: Review over MCP: `nexo_pending_reviews`, `nexo_get_review` and `nexo_submit_review` on `nexo mcp` (`MCP_REVIEW_TOOLS`, on by default); the write asks the person to confirm by elicitation and refuses clients that cannot ([MCP server](components/mcp-server.md#review-tools), [ADR-0019](decisions/adr-0019-review-surfaces.md)).
* **Update**: Review has a shared core: `Runtime.pending_reviews()` lists paused threads and `Runtime.review_passages()` reads the cited chunks for a clearance, masked by the redactor ([Human review](operations/human-review.md), [ADR-0019](decisions/adr-0019-review-surfaces.md)).
* **Update**: [Judge scores](operations/evaluation.md#judge-scores) on a small Mac: pull a judge, then `JUDGE_MODEL=... nexo eval` or `roles.judge` in `nexo.yaml`; a judge named for a profile that turns it off now runs on that profile's Ollama instead of the vLLM default.
* **Update**: Chunk text and embeddings live on the graph's (:Chunk) nodes (`CHUNK_STORE=neo4j`), so every checkout of a stack sees them; review checkpoints move to `~/.local/share/nexo/<stack>/`; `nexo chunks import` migrates a JSON store ([ADR-0018](decisions/adr-0018-chunks-in-neo4j.md) supersedes ADR-0004).
* **Update**: Chunks above a caller's clearance only because of detected PII spans are shown with those spans masked (`[EMAIL]`), not withheld; PHI, declared levels and unexplained levels stay withheld ([read-time redaction](components/sensitive-data-detection.md#read-time-redaction), ADR-0006 amended). Chunks record `declared_sensitivity`; the golden Delta case runs at `internal` ([Evaluation playbook](operations/evaluation.md)).
* **Update**: The investigator has a third tool, [search_chunks](components/search-chunks.md), and is told absence from the graph is not evidence of absence; tool results report calls left and the tool budget leaves a turn for the answer ([Investigator agent](components/investigator-agent.md)). `nexo eval` accepts `strategy`, `clearance` and `answer_contains` per case, and a golden set covers the sample documents ([Evaluation playbook](operations/evaluation.md)).
* **Update**: Traces say who asked and which question: `user.id`, `session.id` and a keyed hash of the question on request and MCP spans; the question's text is opt-in (`telemetry.queryText`); review pauses no longer export the question and draft answer as an exception ([Observability](operations/observability.md#which-user-and-which-question), ADR-0009 amended).
* **Update**: Docs checked against main: SigNoz login source corrected (the secrets provider, not `.env`), the SELinux `:z` scripts volume documented in the [SigNoz reference](references/signoz.md), [Troubleshooting](operations/troubleshooting.md) gains a local-stack and CI section, and [Testing](operations/testing.md) lists the setup and wiring suites.
* **Update**: The keychain is an optional extra (`make install-keychain`): nothing imports `keyring` unless `secrets.provider: keychain` is chosen, so tests and CI run without it ([Testing](operations/testing.md)).
* **Update**: Generated secrets live in a provider (`spec.secrets.provider`): `~/.config/nexo/config` by default, keychain, SOPS or Vault opt-in; clusters mount them as files read in-process, never environment variables; locally compose gets them through the environment; `check` and `up` log in to Neo4j ([ADR-0017](decisions/adr-0017-secrets-from-a-provider.md), [Choosing a setup](operations/decision-guide.md#9-where-secrets-live)).
* **Creation**: [Choosing a setup](operations/decision-guide.md): decision matrices for presets per hardware, one or two machines, model serving, observability add-ons, memory per combination, flags versus `nexo.yaml`, how to run the services and content in telemetry.
* **Update**: One setup file, `nexo.yaml`, rendered by `nexo setup` (lock, preflight with a memory budget, presets for five setups); `make` keeps its targets and add-on flags; `docker-compose.yml` is generated from the mac-single preset; the GPU and Linux overrides are gone ([How local setup works](operations/local-setup.md), [ADR-0016](decisions/adr-0016-declarative-setup-file.md)).
* **Update**: SigNoz is the default observability backend (traces, metrics, logs, alerts, host and container metrics); Langfuse becomes the `LANGFUSE=1` add-on for evaluation work; the Grafana LGTM add-on is removed ([SigNoz](references/signoz.md), [ADR-0015](decisions/adr-0015-signoz-default-observability.md) supersedes ADR-0014).
* **Update**: Opt-in log export (`OTEL_LOGS_EXPORTER=otlp`) and a Grafana LGTM add-on (`make up LGTM=1`) for traces, stored metrics and logs; new [FAQ](operations/faq.md).
* **Update**: Langfuse is the default trace backend, self-hosted by `make up`; Jaeger and LangSmith are opt-in add-ons (`make up JAEGER=1` / `LANGSMITH=1`); `make env` generates the secrets ([Langfuse](references/langfuse.md), [ADR-0014](decisions/adr-0014-langfuse-default-trace-backend.md) supersedes ADR-0011).
* **Update**: Python and dependencies install with uv (`uv sync`, `uv.lock`, `.python-version`); CI, the Dockerfile, `.mcp.json` and the playbooks use it.
* **Update**: Code follows pylint's defaults and black's formatting (ruff removed); `make lint` runs both ([Testing](operations/testing.md)).
* **Update**: A `Makefile` covers setup, models, services, tests, the walkthrough and the site; CI runs its targets ([Testing](operations/testing.md)).
